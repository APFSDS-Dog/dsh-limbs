## goal

修「Limbs 配置」设置页白屏。现象是点进设置分区就崩，而同一插件的另外四处 `useSyncExternalStore`（模型座位 / 模块二 / 复盘面板 / 项目面板）全好 —— 这个「只坏一处」的分布本身就是线索。

根因不在渲染逻辑，在**数据源的形状**：`createLimbsSettingsStore` 的 `read()` 每次 `return { settings, status, writable }` —— 每调一次就是一个新对象。它被当作 `useSyncExternalStore` 的 `getSnapshot`，而 React 判定快照是否变化**只看引用**，于是它认为状态永在变化 → 无限重渲染 → `Maximum update depth exceeded` → 整个 `settings.section` 崩掉。

连带要补一件事：这个洞**离线测试是绿的**（89 passed / 0 failed），因为测试里的 React 是替身，不跑真实的「引用比对 + 重渲染循环」。所以本轮真正要交的产物是**一条能把这类问题在离线阶段判红的断言**。
