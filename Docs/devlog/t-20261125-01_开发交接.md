### 真机目视暴露的三件事（都修了，值得记）

1. **桌面端不经过 Host 的 `index.html`**：DSH Desktop 从自己的 dist 取文档，再通过
   `dshDesktopBoot.ready()` 拿回 Host 收集的**结构化注入行**（页面侧逐行 apply，
   `kind: 'global'` 就是 `globalThis[name] = value`）。所以 `webServer.tapIndex()`
   在桌面端**无效** —— 页面显示「Host 接口没挂上」而 Host 的路由其实是活的（403）。
   正解：订阅官方 `webserver/index-inject` 事件，把同一份 payload 推成一行 `global`。
2. **桌面端 Origin 是 `dsh-app://app`**：外壳转发 `/limbs/*` 时保留这个 Origin。只按
   「与请求 URL 同 host」判同源 → 桌面端每个请求都 403。已把它列为**唯一额外可信 origin**
   （列表在 `TRUSTED_APP_ORIGINS`，`dsh-app://shell` 等其它 host 仍拒）。
3. **PUT 必须是补丁而不是全集**：第一版 `validateConfigPatch` 从
   `{...DEFAULT_HANDOFF_CONFIG}` 起算，于是「只改 inject」的 PUT 会把没提交的 `write`
   一并写成默认 `false` —— 真机上点一下热注入开关，本项目的 `write: true` 就被抹掉了。
   已改成只返回提交的键，并加了「补丁只含提交键」的断言。
