## confirmed_facts

### 真机现场（修复前）

`/limbs/*` 六条路由**全部 404**，而对照组 `/zzz-not-a-route` 同样是 404、根路径 `/` 是 **401**（鉴权提示）—— 证明 webServer 活着、鉴权正常，**只是路由一条都没注册**。

面板三句话指向同一件事：

| 位置 | 原文 |
|---|---|
| 复盘面板 | 报告没有落盘：读不回落盘文件（本会话是只读权限，或 Host 接口没挂上） |
| 复盘面板下拉 | 读不到模型目录 |
| 项目管理 | Host 接口没挂上（webServer 缺席或插件未启用）…（桥接返回 HTTP 404） |

### 根因

`export const inject = ['tools', 'commands', 'sessions']` 里**没有 `webServer`**，三个桥却都在 `apply()` 里当场 `ctx.get('webServer')`：

```
const webServer = ctx.get('webServer')
if (webServer === undefined) return undefined   ← 静默降级
```

`ctx.get(name)` 默认 `strict = true`，要求**提供该服务的 fiber 已 active**；`webServer` 要异步 bind 端口才完成 `Service.init`，而 `apply()` 一辈子只跑一次 → 拿到 `undefined` → 三条路由永不注册、永不重试。

**判据（区分「插件没加载」与「服务拿不到」）**：`analyze_conversation_efficiency` 与 `handoff_lookup` 在工具表里都在 —— 它们注册在三个桥**之前**，说明 `apply()` 跑到了底、没整体崩，只是三个桥静默跳过。所以不是 disabled、不是包未解析（`include:dsh-limbs` 的 `status` 是 `schema`、`packageDir` 指向本仓库符号链接）。

### 同源的第二处

Client 侧 `limbsReviewFace(ctx)` 在**槽位注册那一刻**把 `ctx.get('modelDirectories')` 取一次存进闭包。同一份服务在 composer 座位里是**惰性**读的（`inject: (sessionId) => …` 里现取），所以座位能列模型、面板报「读不到模型目录」—— **同机两处行为不一致，正是「一处惰性、一处提前」的指纹**。

### 修法

| 位置 | 改动 |
|---|---|
| `lib/host.js` | 三桥改走 `ctx.inject(['webServer'], mountWeb)`（官方 `dsh-backup` / `dsh-providers-live-models` 同款）；`webServer` **刻意不写进 `inject`** —— 写进去会让无 GUI 的 profile 整份插件不激活，连工具与 `/limbs-review` 一起消失 |
| `lib/host.js` | `mountWeb(scope)` 只从 `scope` 取 `webServer`，**其余一切仍走根 ctx**：三个桥内部调 `ctx.effect` / `ctx.on`，那些注册必须挂在插件自己的 fiber 上才会随插件卸载清理 |
| `lib/host-status.js`（新） | 每次启动往 `<DSH_HOME>/dsh-limbs/host-status.json` 写「谁挂了、挂了哪几条、失败原因」 |
| `lib/client.js` | `limbsReviewFace` 改成**每次注入现取**；降级文案从三句并列猜测改成指向诊断文件的单一判据；「服务没挂」与「目录为空」拆成两句 |
| `tools/host-diagnose.ps1`（新） | 真机第一条命令：先立对照组，再探六条路由，最后读诊断文件 |
| `.dev/host-bridge-test.mjs`（新） | 21 条：webServer **迟到** / **缺席** / **重复** 三种时序 |

上一轮我说「源码比进程早 10 小时 → 不用重启」。**这条是错的**。桌面版是主进程 + Host worker（5 个同名进程），且 Host 半侧走 `dsh-hmr` **进程内热替换**，进程启动时间**不会变**。拿进程启动时间比源码时间，在桌面版上不是可靠判据。`tools/host-diagnose.ps1` 里那段已改成：列全部同名进程 + 以 `host-status.json` 的写入时间与 pid 为准。
