# t-20261125-02 · 模块七 令牌死锁修复

> `id` `t-20261125-02` ｜ 2026-11-25 ｜ 状态 **done**

## goal

修模块七的令牌死锁：过去令牌只能由 `/limbs-handoff-token` 发，模型调不了 `ctx.commands`，项目主说「任务收尾」后模型仍拿不到令牌，只能人工代跑命令 —— 四道闸退化成半自动。新增 `handoff_request_token`，发不发由「本轮 user message 里有没有授权语」判定；模型改不了 user message，所以无法自问自答（D0-1 不变，只是把「谁发」换成「按什么判」）。

## confirmed_facts

### 「能读到本轮 user message」是怎么验的（这是本轮的前提，先验后用）

1. **查 API**：翻 `app.asar` 内官方源码，找到官方自己的同一写法 —— `dsh-tool-goal/src/authority.ts:33`
   用 `agent.session.snapshotEvents()` + `ctx.agents.turnBoundaryOf(session).openTurnStartSeq` 读「本轮人类输入」。
   `snapshotEvents()` 虽被官方标 deprecated，但没有「本轮消息」的 Service 替代品，官方插件自己在用。
2. **查真实数据形状**：解压运行中的会话日志（`session.v4.jsonl.zstd`，多帧 zstd，逐帧 `zstdDecompressSync`），
   逐条打印 `user/message` 的 `source`。实测：人类消息 = `{kind:'user', rpcId:'f0530f2d…'}`；
   模块七热层注入 = `{kind:'user'}`（**无 rpcId**）；另有 `agent-instructions` / `runtime-context` / `time-context` 各用各的 kind。
3. **真机实测（正例）**：`unlag_refresh` 换掉活进程里的旧代码后调一次 `handoff_request_token` → 真的发出令牌，
   `sessionId` 是本会话真实 id（不是兜底的 `default`）。
4. **真机实测（反例）**：收紧判据后再调一次（本轮无口令）→ 正确拒绝，理由含「缺口令」。

### 三条判据

- **只能看本轮**：`openTurnStartSeq` 之后的事件；上一轮的口令不算本轮授权。
- **只能看人**：`source.kind === 'user'` **且有 `rpcId`**（官方 `'user-rpc'` 源）。只判 kind 会出事 ——
  热层注入也是 `kind:'user'`，正文里还写着「要收尾请项目主说「任务收尾」」，那就是热层自己授权自己。
- **只能看本会话自己的**：跳过 `inheritedEventCount` 之前的 fork 继承前缀；`header.origin === 'subagent'` 直接拒。

### 真机抓到并修掉的两处自造漏洞（最要紧）

**漏洞一：描述当授权。** 第一版按「正文包含『任务收尾』」判。真机一调就暴露：本轮任务描述里写着
「项目主说「任务收尾」后，agent 无法自己拿令牌」—— 那是**描述**不是下口令，却被判成授权，
等于模型拿描述给自己发令牌，D0-1 当场破。已收紧为「**整句就是口令**」：两侧只允许剥掉纯语气字
（好/行/那就/吧/了…），剥完整串必须等于口令短语；夹在长句里的、被引号包住的、带「我说」前缀的一律不认。
那次误发的令牌（`d637614c…`）已手工作废。原则：**宁可漏认**（代价是项目主再说一遍），也不要误认（代价是绕过授权）。

**漏洞二：两个入口用了不同的记账键。** 真写那次撞上：`handoff_request_token` 把令牌记在
**真实会话 id** 上，而 `commitHandoff` 在没显式传 `sessionId` 时退回 `'default'` →
「令牌明明发出去了，提交却说缺口令（已用过）」—— 死锁换了个地方复发。
已改成缺省取当前会话 id，并补了断言 ③-b 守它（含「该令牌确实被消费掉」的反向核对）。

### 令牌语义

一次性 + **30 分钟 TTL**（`expiresAt`，缺此字段的老记录一律当过期，fail-safe）+ 按真实 sessionId 记账。
过期 / 跨会话 / 用过 / 值不符，四种拒绝理由都带「缺口令」前缀。
