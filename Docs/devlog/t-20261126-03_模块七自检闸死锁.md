两处规则各对一半，合起来没有解 ——

| 谁 | 做了什么 | 后果 |

| `lib/handoff.js` 写盘段 | 只 `writeFile(devlog)` + `writeFile(progress)`，**从不 `git add`** | 新文件不在 git 索引里 |

### 为什么这条 bug 藏了一整轮（本轮最值钱的发现）

副本目录以前**没有 `.git`**。于是 `check_docs.py` 的 `git_tracked_files()` 返回 `None` → 那一项落进 `ok.append((..., None, ...))` → 输出 `⏭️ 跳过`。

**跳过和通过，在测试眼里都是绿的。** 所以 191 条断言全绿，真写却必然失败 —— 这不是断言写少了，是**被守的那条检查从来没真跑过**。

修法不是「多加几条断言」，而是**先把检查的前置条件造出来**（让副本有 `.git`）。造好之后，两条新断言才有意义：

```text
PASS  自检里「任务账存档已入库」这一项真跑了（不是跳过）
PASS  自检里「任务账存档已入库」这一项是 ✅
```

### 红 → 绿的过程（临时把 `stageForCheck` 换成空实现验证）

```
临时关掉 git add：
  FAIL  真写成功（wrote=true） — "工程自检未通过（exit 1），本次写入已撤回…"
  FAIL  真写后自检通过 — 1
  FAIL  自检里「任务账存档已入库」这一项是 ✅ — ❌ 任务账存档已入库
  FAIL  devlog 真的出现了 — [...没有新文件...]

恢复之后：202 passed, 0 failed
```

红在**正确的那几条**上，且报错文案与真机那次一字不差 —— 说明复现是真的，不是造的。
