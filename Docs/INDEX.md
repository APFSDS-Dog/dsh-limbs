# 文档索引（Docs/）

> **⚠️ 本目录不随包发布。** `package.json` 的 `files` 不含 `Docs` —— 用户装到的只有 `README.md`。
> 这里装的是**工程治理文档**（设计 / 决策 / 踩坑 / 任务记录）。规则见 `DOCS_LAYOUT.md` §⑮·1。
>
> 本目录是《dsh-limbs》的**统一文档中心**。
> 所有设计、技术、日志、归档文档都收在这里，方便整体管理、备份与迁移。
>
> ⚠️ **本文件只回答「有哪些文件、放哪」** —— **不写内容摘要**（那是文档自己的事），
> **不写职责边界**（那是 `DOCS_LAYOUT.md` 的事，唯一源）。

## 目录结构

```
Docs/
├── INDEX.md      ← 你在这里
├── design/       设计文档（要什么、为什么）
├── tech/         技术文档（怎么搭、怎么配、机器环境）
├── devlog/       开发日志（按任务追加，永远不改旧的）
├── archive/      归档（已废弃 / 被取代，只进不出）
└── （discussions/ 只在真有跨会话讨论时新建，不预设空目录）
```

## 编码与命名约定

| 项 | 约定 |
|---|---|
| 编码 | **UTF-8**（是否带 BOM 按仓库惯例统一，别一处一个样） |
| 命名 | `YYYY-MM-DD_<类型>_<主题>.md` —— 日期在前，便于排序（**`devlog/` 例外**：用任务 `id` 前缀） |
| devlog | `t-YYYYMMDD-NN_<内容摘要>.md`（摘要 4–12 字；接手时取 `id` 最大的那份；`t-` 前缀保证字典序 = 时间序） |
| 归档 | 用 `git mv` 移入，**保持原文件名**（改名会让旧引用悬空） |
| 行尾 | 按仓库现状，**以 git HEAD 为准**，别一刀切 |

**归档怎么做**（与"改名"是两回事，别混）：

- **归档** → `git mv` 进 `Docs/archive/`，**保持原文件名**（加 `_已归档` 之类后缀会让活文档里的旧引用悬空）
