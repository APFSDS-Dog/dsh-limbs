# DSH 控制台插件 PRD（v0.3）

> 定位：面向 DSH 的 AI 工作流控制台插件。
> 原则：Shell 只承载不越界；右侧团队常驻并行；治理入口分层；不推翻已做功能。
>
> **v0.3 变更（2026-11-20）**：新增 **模块 7 · 窗口交接**（治理层第三个触发点，与 3/4 同管线）；
> 它此前被误编为「模块五」，与本文档的模块 5（受控值守）撞号，已改正。路线图阶段 1 同步插入。

## 1. 布局总览（按实际骨架）

```text
┌────────┬──────────────────────────┬──────────────┐
│ 左侧   │        中间对话区          │  右侧视图栏   │
│ 竖条栏 │                          │ （常驻并行）  │
│        │                          │              │
│ 新建对话│   对话窗口                │ AI团队协作    │

│        │                          │ 复盘/diff卡片 │
├────────┴──────────────────────────┴──────────────┤
│ 底部状态栏：模型 / 推理强度 / 急停                  │
└──────────────────────────────────────────────────┘
```

布局约束：
- 左侧竖条栏：新建对话 + 后期“对话中上下文治理”入口 + 值守入口。
- 中间对话区：对话主通道，不替换。
- 对话区下方：**不再放档位条**（模块 2 不做，见 §5）。推理档位在输入框模型选择器底部用 chips 切换。
- 右侧视图栏：常驻并行，AI 团队协作不被对话顶替；复盘/diff/产物以卡片或分区叠加。
- 设置栏：承载“模型 API 配置、档位治理、通用设置”等设置拦截界面。
- 底部状态栏：展示实际生效值（模型、推理强度）。

架构关系：

```text
Shell（容器，只承载不越界）
  ├─ 控制层：模块 1 / 2 / 2b
  ├─ 治理层：模块 3（事后） / 4（即时） / 7（任务边界）
  ├─ 执行层：模块 5
  └─ 观测层：模块 6（右栏常驻）
公共底座：配置中心 + 审计日志 + 回滚快照 + 事件总线
```

> **治理层为什么是三个不是两个**：3/4/7 共用同一条管线（采集 → 诊断 → 策略 → 执行 → 审计），
> 区别只在**触发点**：复盘是「事后」，整治是「超阈值即时」，交接是「任务边界」。
> 三者共用同一套事实表示 schema，**不各写各的**（见 §8b）。

## 3. 模块 0：Shell 框架（只承载，不越界）

### 3.1 职责边界
- 做：区域划分、模块注册、插槽挂载、状态栏订阅、空态占位、通知入口。
- 不做：不定义各模块业务内容；不替模块做配置页；不替团队视图做业务逻辑。

### 3.2 区域与插槽

| 区域 | 定位 | 现状 | 挂什么 | 协议 |
|---|---|---|---|---|
| 左侧竖条栏 | 会话与治理入口 | 骨架空 | 新建对话、后期治理入口、值守入口 | 入口注册 |
| 中间对话区 | 对话主通道 | 已有 | 对话本身 | 不改 |
| 对话区下方 | 运行档位条 | **不做** | —（模块 2 不做，档位在模型选择器 chips 里） | — |
| 右侧视图栏 | 常驻并行视图 | 骨架空 | 模块 6 团队协作（常驻）、模块 3 复盘卡、模块 4 diff 卡、产物 | 视图卡片注册，不可被顶替 |
| 设置栏 | 配置与治理界面 | 骨架空 | 模块 1 模型API配置、模块 2b 档位治理、通用设置 | 配置 schema 注册 |
| 底部状态栏 | 实时生效值 | 骨架空 | 模型、推理强度、审计状态、急停 | 状态订阅 |
| 通知/审批中心 | 人工介入 | 未做 | 值守审批、整治确认、告警 | 事件注册 |

### 3.3 插槽协议（骨架阶段最重要）
每个功能模块注册时声明：
- 区域：左栏 / 主区 / 右栏 / 设置 / 状态栏
- 所需配置：读取哪些配置项
- 是否需要审批入口
- 是否产生审计事件
- 状态订阅：需要底部状态栏展示什么
- 右栏卡片：是否常驻、是否可折叠、是否可切换

### 3.4 MVP
导航 + 主内容区插槽 + 底部状态栏 + 设置页壳 + 通知入口，全部空实现。

### 3.5 验收标准
- 新增一个功能只需注册，不改 Shell 核心代码。
- 右侧团队视图常驻，切对话不消失。
- 底部状态栏能显示模块 1 与推理档位的实际生效值。
- 设置栏能按 schema 渲染配置项。
- 左右栏空态有明确占位说明，不显示空白。

### 3.6 风险
- 骨架阶段过早做复杂路由/状态管理。
- 每个功能自带设置页导致重复。
- 左右栏定位不清，变成“什么都能塞”。
- 右栏空间有限，团队常驻与复盘/diff 卡片冲突。

## 4. 模块 1：模型选择面板

- 解决什么：模型选择不直观，切换成本高。
- 输入：模型列表、能力标签、上下文/费用信息。
- 输出：当前模型、实际生效配置。
- MVP：美化 + 搜索 + 能力标签 + 持久化 + 快捷键。
- 验收：切换后立即显示实际生效值；刷新不丢；可搜索。
- 风险：只改外观不改配置链路，出现“看起来切了但没生效”。
- 挂载：主内容区面板 / 设置栏；底部状态栏显示当前模型。

## 5. 模块 2：运行档位面板 —— **不做**（2026-11-26 决定）

> **状态：不做。** 本章保留，是为了让人知道"想过、为什么不做"，不是待办。

- ~~解决什么：推理强度、上下文档位分散，用户不知道组合效果。~~
- ~~输入：推理强度、上下文预算、项目/会话覆盖。~~
- ~~输出：快速/标准/深度/自定义档位。~~
- ~~MVP：组合预设 + 实际预算显示 + 冲突检测 + 自动降级提示。~~
- ~~挂载：对话区下方档位条；底部状态栏显示档位与实际预算。~~

**为什么不做（两条，分开说）**：

1. **上下文挡位是假控件。** 代码里从未把 `context` 传给模型请求 —— 存了不生效。
   一个存得住、改得动、却对真实请求毫无影响的旋钮，比没有它更坏：它让人以为自己调了预算。
   相关实现（300K / 600K / 1M 枚举、设置项、Host Config 的 `context` 字段）已一并删除。
2. **档位条滑杆与 chips 功能重复，且 chips 更轻。** 选择器底部的推理档位胶囊一眼看全 5 档、
   单击即选；滑杆要多一步拖动/吸附/键盘操作才达到同样的效果，属于重复实现一条更重的路径。
   滑杆组件（`LevelSlider`）与其整套 CSS、断言已删除。

**保留什么**：推理档位 chips（提供方默认 / Off / Low / High / Max）。它**真进 provider 的 effort**，
是这件事里唯一有效的那部分，位置与交互都不动。

> 由此本模块从"P0 收尾"降级为"不做"，不再占对话区下方的位置，也不进底部状态栏。

## 6. 模块 2b：模型API与档位治理界面（设置栏）

- 解决什么：现有模型 API 输入栏目不好用，档位不清晰，缺治理入口。
- 输入：API 配置、模型映射、档位默认值、治理策略。
- 输出：清晰的配置界面 + 校验 + 生效提示。
- MVP：API 配置表单 + 校验 + 档位默认值 + 治理开关占位。
- 挂载：设置栏。
- 验收：配置可校验、可保存、可回显实际生效值。
- 风险：设置项散落，需统一 schema。

## 7. 模块 3：事后复盘

- 解决什么：会话结束无沉淀，关键决策和产物丢失。
- 输入：会话记录、工具输出、文件变更、错误。
- 输出：复盘报告：做了什么/为什么/产物/问题/待办/下次记忆。
- MVP：模板化复盘 + 产物链接 + 可编辑 + 写入记忆前确认。
- 验收：每次会话生成结构化复盘；关键决策不丢；可追溯。
- 风险：摘要丢关键信息；无 diff 不可信。
- 挂载：右侧视图栏卡片 + 审计日志。

---

## 8. 模块 4：即时整治 / 对话中治理

- 解决什么：上下文过长、重复、工具输出污染。
- 输入：每轮对话、超阈值触发、工具输出。
- 输出：去重/截断/摘要后的上下文 + 整治 diff + 审计日志。
- MVP：规则版优先：超阈值、重复内容、工具输出截断、保留决策/错误/待办、敏感信息标记。
- 验收：整治前后可 diff；关键信息保留；可回滚；有日志。
- 风险：一上来全靠 LLM 摘要，不可控且贵。
- 挂载：左侧竖条栏治理入口 + 右侧视图栏 diff 卡片 + 通知确认 + 审计日志。
- 说明：模块 3/4 同属治理管线：采集 → 诊断 → 策略 → 执行 → 审计；即时整治与事后复盘只是不同触发点。

## 8b. 模块 7：窗口交接（任务边界触发）

> 施工规格见 `Docs/design/MODULE7-HANDOFF.md`（五项 API 已在本机验证）；**本节目的是把它放回整体规划里**，不重复实现细节。

- **解决什么**：换会话就失忆。上下文压缩只在当前会话内减负，跨会话的"做到哪了"没有落点，于是每个新窗口都要重新问一遍。
- **输入**：任务界面上已收尾的任务（`id` / 结论 / 证据位置）、项目现有的账本与冷存档。
- **输出**：写进**工程文件**的交接（不是存进插件自己的库）——一行账 + 一份冷存档正文。
- **触发**：**任务边界，不是水位**。项目主说「任务收尾」才写；程序只做"提醒"，不做"触发"。
- **MVP**：
  1. `assemble`：会话首步注入热层四段（账表最近若干行 / 待拍板全部 / 实测快照 / 上次遗留）。
  2. `lookup`：按 `id` 取冷存档、按关键词检索账表。
  3. `commit`：口令即一次性令牌 → 生成 `id` → 写冷存档 → upsert 账行 → 跑工程自检；**第一版只 dry-run**。
- **验收**：同一天第二次收尾得 `-02`；重复喊口令不产生第二份；没说口令写不进去；卸载后 `ctx.effect` 清干净。
- **风险**：
  - 每步注入会改写 prompt 前缀 → 缓存命中率下降。**只在会话首步 / 任务边界注入一次。**
  - 在没有口令的情况下"自作主张记一笔"，会让账本被 AI 污染 —— 所以令牌是**授权**，不是去重。
  - 与模块 3/4 各写一套摘要结构 → 三套 schema。**必须先定一套事实表示，7 复用它。**
- **挂载**：**无 UI**。纯 Host 半边（`agent/pre-step` + 工具注册），不占左栏/右栏/设置任何格子。
- **与 3/4 的关系**：同一条治理管线的第三个触发点。3 是事后复盘、4 是超阈值即时整治、7 是任务边界主动换轨。
  **7 的产出是工程文件，3 的产出是报告** —— 落点不同，但共用 `goal / confirmed_facts / excluded_paths / todos` 这套事实表示。

## 9. 模块 5：受控值守/离线化

- 解决什么：希望类似“仅在工作区修改”的受控自动执行能力。
- 输入：任务、工作区白名单、命令白名单、预算。
- 输出：自动执行记录、变更 diff、回滚点、审批点。
- MVP：只允许工作区改文件 + 命令白名单 + 变更预览 + 一键回滚 + 步数/时间/token/费用上限 + 急停。
- 验收：越界操作被拦截；每步有日志；可回滚；可人工审批。
- 风险：直接叫“无人化”容易失控，先叫“受控值守”。
- 挂载：左侧竖条栏入口 + 主区执行面板 + 底部状态栏急停 + 审批中心。

---

## 10. 模块 6：AI 团队协作（右侧视图栏常驻）

- 解决什么：现有对话模式不直观，团队协作和产物管理弱。
- 输入：角色、任务、依赖、消息、产物。
- 输出：角色卡、任务看板、运行日志、产物链接；依赖图后置。
- MVP：角色列表 + 任务看板 + 运行日志 + 产物链接。
- 验收：切对话不消失；任务状态可见；产物可跳转；底层仍可回到对话。
- 风险：过度设计拓扑图；右栏空间有限，需折叠/分组/标签页。
- 挂载：右侧视图栏常驻，与对话并行，不被顶替。

## 12. 路线图

### 阶段 0：收口现有（P0）
- 建配置中心、审计日志雏形。
- Shell 插槽协议落地，左/右/设置/状态栏空态占位。
- 模块 1 与推理档位 chips 接入配置中心与状态栏。
- 设置栏骨架接入模块 2b 的 schema 占位。
- 验收：配置不丢、实际生效值可见、项目/会话可覆盖。

### 阶段 1：上下文治理（P1，当前主线）
- 治理管线：采集 → 诊断 → 策略 → 执行 → 审计。
- 即时整治规则版（左栏入口 + 右栏 diff）。
- 事后复盘模板化。
- **先定一套事实表示 schema**（`goal / confirmed_facts / excluded_paths / todos`）—— 3 / 4 / 7 共用，**这一步是 7 的前置**。
- **模块 7 窗口交接**：`assemble`（只读）→ `lookup`（只读）→ `commit`（先 dry-run）。不占 UI。
- 整治前后 diff + 可回滚。
- 模块 2b 配置界面落地：API 输入、档位默认值、校验与生效提示。
- 验收：关键决策/错误/待办保留；压缩可解释；复盘可追溯；**新会话不再重问已定的事**。

### 阶段 2：受控值守（P2）
- 工作区围栏、命令白名单、变更预览、回滚快照、预算与急停。
- 验收：越界拦截、每步日志、可回滚、可审批。

### 阶段 3：团队视图（P3）
- 右侧常驻团队协作：角色卡、任务看板、运行日志、产物链接；依赖图后置。
- 验收：任务和产物可管理，底层对话不受影响，切对话不消失。

## 13. 设计原则

1. Shell 只承载不越界。
2. 右侧团队常驻并行，不被顶替。
3. 治理入口分层：左栏入口 + 右栏卡片。
4. 规则优先，LLM 后置。
5. 所有自动动作可审计、可回滚。
6. 图形化是上层视图，不替代对话。
7. 每个功能必须有验收标准，避免范围膨胀。
8. 设置项统一 schema，不各做一套。

---

## 14. 风险登记

| 风险 | 影响 | 对策 |
|---|---|---|
| 上下文压缩丢关键信息 | 治理不可信 | 保留决策/错误/待办/偏好，提供 diff |
| 自动执行破坏工作区 | 数据损失 | 围栏、预览、回滚、预算、急停 |
| 图形化团队过度设计 | 成本高 | 先看板，依赖图后置 |
| 右栏空间有限 | 团队与复盘/diff 冲突 | 折叠/分组/标签页 |
| 设置项散落 | 维护难 | 统一 schema |
| Shell 越界 | 越加越乱 | 只注册不定义业务 |
