# 踩坑录（可复用的教训）

> **坑跟知识走，不跟任务走。** 一条坑只要换个任务还会再踩，就该在这里；
> 只属于某次任务的细节 → 那份 `Docs/devlog/t-*`。
> 每条格式：**现象 → 根因 → 绕法**。只写现象不写根因的，等于没记。

## 插件侧（DSH / WebView2）

### #1 · 「配置」点了没反应

- **现象**：底栏「配置」毫无反应，设置面板不弹。
- **根因**：代码只找 `aria-haspopup="dialog"` 且 `aria-label` 含「设置」的按钮。本构建里那按钮不存在 —— `settings.launcher` 被账号行占了，设置是**账号菜单里的一行**（`aria-label="账号菜单"` + `aria-haspopup="menu"`）。
- **绕法**：两种布局都试；先试 dialog 按钮，找不到就点账号菜单再点「设置」。

### #2 · 面板弹了但停在「账号与余额」

- **现象**：能打开面板，但不是「模型」页。
- **根因**：两个叠加 —— ① 面板刚挂载时导航按钮还没渲染，代码立刻返回且不再重试；② 菜单项文字带快捷键后缀，`label === '设置'` 精确比较命中不了，而放宽成 `startsWith` 又会把**菜单容器**算进去，点了等于点空。
- **绕法**：轮询到导航按钮出现再点；菜单项只匹配可点击元素（`button` / `[role=menuitem]` / `[role=button]` / `a`），且只容忍短快捷键尾巴（`labelIsRow`）。

### #5 · 窗口标题带会话名

- **现象**：按标题 `DeepSeek Harness` 精确匹配找不到窗口。
- **根因**：实际标题是「继续设置面板快捷入口任务 — DeepSeek Harness」。
- **绕法**：改包含匹配。另注：本机 `MainWindowHandle` 返回 **0**，必须 `EnumWindows` 找句柄。

### #7 · 残留 `<style>` 让热重载永远显示旧 CSS

- **现象**：连着三次改配色，看起来「完全没生效」。
- **根因**：注入代码原本是「`#dsh-limbs-styles` 已存在就跳过」。热重载换掉了模块，**但上一轮追加的 `<style>` 还在页面里**，于是新 CSS 一次都没装上。
- **绕法**：先 `remove()` 同 id 旧元素，再**无条件**写入当前 CSS 文本；卸载仍由 `ctx.effect` 的 cleanup 负责。

### #8 · CSS 注释里的反引号把模板字符串截断

- **现象**：整个插件解析失败、界面全无；而 `node --check` 照样 exit 0。
- **根因**：`const CSS = \`` 是大模板字符串，注释里写了个含反引号的路径，直接把字符串提前结束。
- **绕法**：注释里去反引号；并在 `.dev/ui-shell-test.mjs` 加「源码卫生」断言（CSS 体长度 > 2000、体内反引号数 = 0、关键选择器存在）—— 同类问题下次**当场红**。

## 桌面自动化侧（Windows）

### #3 · 模拟点击落进了 Photoshop（**最贵的一条**）

- **现象**：点完 DSH 界面没反应，截图拍到的是 Photoshop。
- **根因**：`SetForegroundWindow` 在 Windows 上并不总能成功把窗口提到前台；`mouse_event` 是**真实系统级输入**，点到的是当前最上层窗口。DSH 被别的程序挡住时，点击就落进别的程序。
- **绕法**：`tools/chain.ps1` 点击前调 `IsForegroundOf($hwnd)`，不是前台就报错退出（exit 2），绝不盲点。
  > **任何模拟点击脚本都应该带这道闸。**

### #4 · 截图与 UIA 状态对不上

- **现象**：UIA 报按钮在 y=833，截图里却在 y=530。
- **根因**：`PrintWindow` 对 WebView2 只返回可见条带（窗口 1400px 高，图 903px），坐标基准被打乱。
- **绕法**：改用 `GetClientRect` + `ClientToScreen` + `CopyFromScreen`，并在**同一进程内**一次取完几何 / UIA / 截图（`tools/state.ps1`）。

### #6 · `pwsh -File` 的数组参数会被空格拆坏

- **现象**：`-Steps 'a','b c'` 被当成一整串。
- **绕法**：改成单个字符串 + `;;` 分隔。

## 样式与主题

### #9 · 主按钮不能用 `brand-primary` 打底配白字

- **现象**：浅色主题下好看，深色主题下白底白字。
- **根因**：`--dsw-alias-brand-primary` 在**深色主题下是近白色**。
- **绕法**：主按钮别用 `brand-primary` 打底。开关的圆钮永远取与轨道**相反**的那个 token：
  - 关 = `label-primary` 圆钮压在 34% 轨道上
  - 开 = `bg-base` 圆钮压在满强度轨道上

  **两种主题都成立。**

**本机 token 实测值**（从截图像素反解，不是肉眼调；对照 `ui-theme/lib/client.js`）

| token | light | dark |
|---|---|---|
| `--dsw-alias-label-primary` | `#0f1115` | `#f9fafb` |
| `--dsw-alias-bg-base` | `#ffffff` | `#151517` |
| `--dsw-alias-brand-primary` | 亮色系 | **近白** |

> 轨道 `rgb(62,62,63)` 对得上 12% 白叠底；圆钮 `rgb(21,21,23)` 对得上 `bg-base`。

## 流程

### #10 · 清理临时文件时把 `package.json` 删没了

- **现象**：发布后清理 `.dev/awesome/` 与 `%TEMP%`，`package.json` 从磁盘消失。
- **根因**：**未确证**。清理范围与现象之间没找到确凿链路。
- **绕法**：`git checkout -- package.json` 从首个提交恢复。
- **教训**：**删文件这类动作，事后能恢复 ≠ 当时没风险。** 清理前先 `git status` 快照，或把清理改白名单。

### #11 · 同一插件提交了两个大小写不同的市场条目

- **现象**：`APFSDS-Dog__dsh-limbs.yml` 与 `apfsds-dog__dsh-limbs.yml` 在 GitHub 上是两个文件，市场会读成两条记录，**而 CI 全绿**。
- **绕法**：一个插件永远只用一个文件名，认准已合并的那个（本插件 = 全小写）。提新插件前先 `gh pr list --author "@me" --state all`。
